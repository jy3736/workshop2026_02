一、系列定位與脈絡

二、工作坊簡介

上一場工作坊，我們練習把教學需求說清楚，並與 AI Agent 協作完成可檢查、可修正的小任務。這一場將把這個能力真正做成一個可用的教學工具：教師帶著自己正在教授的主題、教材、講義或簡報進場，與 AI Agent 協作產生一份多題式選擇題題組（例如 10、20 或 30 題），再以 vibe coding 的方式，把題組與功能需求交給 AI，製作一個可在個人電腦本機開啟的靜態 HTML 自主練習小工具。

選擇題作為起點，是因為規則清楚、容易批閱，對初次嘗試的教師與學生都較友善。AI 可協助教師整理與初步產生題組，但題目是否符合學習目標、答案是否正確、題幹是否清楚、選項是否合理，仍必須由教師檢核這個過程正是在練習把教學專業轉為可以交給 AI 協助處理、但仍由人負責驗收的內容。

學生開啟網站時只看得到題目與選項，作答期間不會看到答案；完成作答並按下「送出並查看結果」後，網站才根據題組中的答案自動批閱，顯示答對題數、總分與逐題對錯，並可重新作答，反覆練習。學生也能把答錯的題目帶去與 AI 對話，追問為什麼答錯、正確概念是什麼、可能誤解了哪裡，形成「教材 → 題組 → 自主作答 → 自動回饋 → AI 釐清迷思 → 再次練習」的學習循環。

本場的目標不是做出一套正式考試系統，而是完成一個可實際試用的自主學習原型。教師將親手體驗：只要能把需求說清楚，AI Agent 就能協助把教學想法逐步做成工具，也能在日後持續依自己的教學需要延伸與修改。

四、學習成果

完成本場後，您將能夠：

  • 設計學生利用 AI 釐清答錯原因、補強觀念的使用情境。
  • 以同儕試用找出操作不清楚或需修正的地方。

  • 送出後顯示答對題數、分數與逐題對錯。
  • 可重新作答，讓學生反覆練習。
  • 題組資料與網頁程式保持清楚分工，方便日後更換教材或修改題目。

七、使用定位與範圍

本場產出定位為學生課後的自主練習小工具，不作為正式成績判定或高風險測驗。學生是否真實投入練習，仍取決於其學習動機；學生也可能利用 AI 取得答案。因此，本工具的價值在於提供可反覆練習、即時回饋與觀念釐清的學習機會，而不是取代教師對正式評量的設計與判斷。

  • 先完成小而可驗收的版本，再依使用經驗改進；不在時間有限的現場追求技術複雜度。
  • 題目、答案、學習目標對應都必須由教師檢核，不可自動採用 AI 產出。
  • 不在 AI 對話中貼入學生個資或完整成績；素材以教師自身教材、講義或簡報為主。
  • 若日後需要正式評量、跨班長期使用、個資處理、資料庫、權限或即時追蹤，應另行規劃資料治理、資安、無障礙、維運與校內程序。

  • 一個送出後才顯示答案、分數與逐題回饋的完整流程。

九、銜接工作坊（三）

工作坊（三）「從自主練習到課堂形成性評量」會延續本場的題組格式與學生作答介面，把課後自主練習帶回教室：學生在課堂中透過教師提供的網址載入指定題庫，填寫班級座號或匿名代碼等最小必要識別資料後完成作答；交卷後系統自動批閱並回傳個人結果。教師端會有一個刻意維持最低必要功能的 Dashboard，只在學生登入開始作答與交卷後顯示必要資訊，全班交卷後可查看各題答對率、錯誤率與常見錯誤分布，並可交給 AI 協助整理成簡單的學習分析。

1. Series Positioning and Context

This is the second of three workshops in the "AI Agent Teaching Applications Workshop" series, designed for university faculty without an engineering background. Across three progressive, hands-on sessions, the series helps teachers see AI moving beyond a simple chat or prompting tool into an AI Agent that can help operate computer and cloud workflows. The core method transfers across tools: state the goal, context, constraints, and completion criteria clearly; check the results; then revise in small iterations.

This session builds on the AI collaboration method from Workshop (1), turning a teacher's teaching content into a question set and tool that students can practice with after class. The question-set format and the submit/feedback logic completed here carry forward directly into the classroom formative-assessment prototype in Workshop (3).

Why the underlying tools were built with Claude Code, yet the materials ask you to use Codex: This workshop teaches how to collaborate with an AI Agent — stating requirements clearly and iterating your way to a static web tool — not tied to any specific product. The custom skills under .claude/skills/ (download-exam-pdf, slice-exam-pdf, clean-exam-question-images, build-quiz-app) were originally built by the instructor using Claude Code; but the live workshop, and the step-by-step Module 1–4 materials, all ask participants to use Codex instead of Claude Code. That's a deliberate choice: the same tools and the same learning path produce the same working result even after swapping the AI Agent used to operate them, from Claude Code to Codex — direct evidence that "the core method transfers across AI tools" isn't just a slogan. If you want to verify it the other way around, you're welcome to redo the same path with Claude Code and see if you land on the same result. It isn't limited to these two tools either: any AI Agent with comparable capabilities (GitHub Copilot Workspace, Spark, etc.) should in principle work too; the instructor has just only concretely verified Claude Code and Codex so far.

2. Workshop Overview

In the previous workshop, we practiced stating teaching needs clearly and collaborating with an AI Agent on small, checkable, correctable tasks. This session turns that skill into an actual usable teaching tool: teachers bring a topic, teaching material, handout, or slide deck they are currently teaching, collaborate with an AI Agent to produce a multiple-choice question set (for example 10, 20, or 30 questions), and then use vibe coding to hand the question set and feature requirements to the AI to build a static HTML self-practice tool that runs locally on a personal computer.

Multiple-choice questions are the starting point because the rules are clear and easy to grade, which is friendlier for teachers and students trying this for the first time. AI can help teachers organize and draft an initial question set, but whether the questions match the learning objectives, whether the answers are correct, whether the stems are clear, and whether the options are reasonable must still be checked by the teacher — this process is exactly where teaching expertise turns into content that AI can help process, while a human remains responsible for sign-off.

When students open the site they see only the questions and options; answers are not shown while answering. After finishing and clicking "Submit and view results," the site auto-grades against the answers in the question set, showing the number correct, the total score, and right/wrong per question, and lets students retry as many times as they like. Students can also bring questions they got wrong to an AI conversation, asking why they got it wrong, what the correct concept is, and where they may have misunderstood — forming a learning loop of "materials → question set → self-practice → automatic feedback → AI clarifies misconceptions → practice again."

The goal of this session is not to build a formal exam system, but to complete a self-learning prototype that can actually be tried out. Teachers will experience firsthand that, as long as they can state their requirements clearly, an AI Agent can help turn a teaching idea into a tool step by step — and that they can keep extending and modifying it later according to their own teaching needs.

3. Who Should Attend

  • Faculty who attended Workshop (1), or who can briefly describe their teaching needs using "goal, context, constraints, completion criteria."
  • Faculty who want to turn a topic, material, handout, or slide deck they are teaching into a multiple-choice question set and web tool students can practice with on their own.
  • Faculty who want students to practice at their own pace after class, get immediate feedback, and clear up misconceptions.
  • Faculty who prefer to first finish a small, complete, locally usable teaching prototype rather than starting with a complex system.

4. Learning Outcomes

After completing this session, you will be able to:

  1. Collaborate with an AI Agent to produce a multiple-choice question set from your own course topic or materials, and check the quality of the questions, answers, and options.
  2. Break a self-testing requirement into question-bank data, screens, interaction rules, and acceptance criteria, and use vibe coding to build and modify a single-page HTML self-practice tool with AI.
  3. Design a basic learning flow that hides answers before submission and only provides a score, per-question results, and feedback after submission.
  4. Explain how students can use their graded results as a starting point to talk with AI to clarify why they got a question wrong and what they have not yet learned.
  5. Use a try-out and acceptance checklist to verify the site matches the original teaching requirements.

5. Focus Points and Minimum Viable Features

Workshop focus points:

  • Collaborate with an AI Agent to organize teaching materials, handouts, or slide decks into a practicable question set, keeping the question bank and the web page cleanly separated.
  • Build the question and option screen, and record student answers.
  • Use vibe coding to complete submission, scoring, per-question correctness, and correct-answer feedback.
  • Add a retry feature so students can practice repeatedly.
  • Design a usage scenario where students use AI to clarify wrong answers and reinforce concepts.
  • Use peer try-outs to find unclear or broken parts of the flow.

Minimum viable features (this session's acceptance baseline):

  • The teacher can build a multiple-choice question set from their materials.
  • The tool can load question, option, and answer data.
  • Answers, scores, and per-question hints are hidden before and during submission.
  • After submission, the tool shows the number correct, the score, and right/wrong per question.
  • Students can retry to practice repeatedly.
  • Question-set data and the web page code stay cleanly separated, making it easy to swap in different materials or edit questions later.

6. Preparation Checklist

  • Bring a laptop and confirm you can use a web browser.

7. Scope, Positioning, and Limitations

This session's output is positioned as an after-class self-practice tool for students, not as formal grading or a high-stakes test. Whether students genuinely engage with practice still depends on their motivation, and students may also use AI to get the answers directly. The tool's value therefore lies in offering an opportunity for repeated practice, immediate feedback, and concept clarification — it does not replace a teacher's design and judgment for formal assessment.

  • Finish a small, checkable version first, then improve it based on real usage; do not chase technical complexity within the limited session time.
  • Questions, answers, and the mapping to learning objectives must all be checked by the teacher — AI output cannot be adopted automatically.
  • Do not paste student personal data or full grades into AI conversations; source material should mainly be the teacher's own materials, handouts, or slides.
  • If formal assessment, long-term cross-class use, personal-data handling, databases, permissions, or real-time tracking are needed later, plan data governance, security, accessibility, operations, and institutional procedures separately.

9. Bridge to Workshop (3)

Workshop (3), "From Self-Practice to Classroom Formative Assessment," continues this session's question-set format and student answering interface, bringing after-class self-practice back into the classroom: students load an assigned question bank via a URL the teacher provides during class, enter minimal necessary identifying information such as a class seat number or an anonymous code, and complete the answers; the system auto-grades on submission and returns individual results.
