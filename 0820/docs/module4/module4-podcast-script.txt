大家好，歡迎回到深度解析節目，這是系列的第四集，也是最後一集。前面三集，我們搭好了環境，把考古題 PDF 變成問題集資料夾，又親手從零設計了一套會產生測驗網頁的工具。這一集要做的事情，其實很簡單：把前面辛苦拆解的那一整套流程，濃縮成一句話。

先講清楚這一集的定位。如果你已經跟著前面走完第三個模組，弄懂了分析資料夾、設計設定檔、打造網頁樣板、寫打包程式、驗收成果、打造教師端頁面這六個步驟，那這一集，就是給你的捷徑版：只用一句話，請 Codex 套用工作坊講師事先寫好的 build-quiz-app 這個現成工具，直接生成一個不用架站、雙擊就能打開的學生自我測驗網頁，外加教師端成績彙整頁，不需要自己讀分析報告，也不需要手動寫設定檔。如果你還沒走完第三個模組，或者當時卡在某個步驟沒跟上，這一集也完全可以直接照做，只是背後那些細節，是交給 Codex 一次做完，而不是你自己一步一步來。

這裡有一個小細節值得先提醒。第二、第三個模組用的那些現成工具，放在專案裡的 .claude/skills 資料夾底下；但這一集用的 build-quiz-app，是放在 .agents/skills 底下這個資料夾。為什麼要特別講這個路徑？因為 Codex 不像某些工具那樣，會自動偵測專案裡有哪些工具可以用，所以下指令的時候，得直接把工具放的位置講清楚，讓 Codex 能直接找到並使用。如果你的專案裡還沒有這個 .agents 資料夾，模組裡有提供一個壓縮檔可以下載，解壓後把資料夾放到專案根目錄，跟其他模組資料夾同一層就可以了。

那一句話怎麼下呢？其實就是直接跟 Codex 說：請對某個問題集資料夾，套用本專案內的 build-quiz-app 這個工具。Codex 讀完工具的說明之後，會自己決定輸出的 app 資料夾要蓋在哪裡——原則跟第三集講的一樣，跟問題集資料夾平級；自己跑資料夾分析、自己寫設定檔、自己打包，你完全不需要插手中間任何一步。看到 Codex 回報完成之後，直接進入驗收就可以了。

驗收的重點，其實跟第三集是同一套邏輯，只是這裡你不需要自己動手檢查每個中間產物。第一，輸出資料夾底下，應該出現一個新的測驗網頁檔案，檔案大小大約是問題集圖片總大小的一點三七倍，這是 base64 編碼膨脹造成的，如果明顯小很多，通常代表圖片沒被完整塞進去。第二，直接雙擊打開那個檔案，不要另外開伺服器，輸入姓名、選一個較小的題數、作答幾題、按送出，確認會出現分數跟逐題對錯的畫面。第三，如果 Codex 回報有題目因為缺圖被跳過，先自己確認能不能接受這個結果，不要視而不見，答案檔裡的題目數跟畫面上能抽到的題數，應該要吻合。

測驗網頁做好之後，還有教師端這一塊。學生在測驗頁面送出作答後，畫面上會有一顆下載成績單的按鈕，把這次作答的逐題結果存成一個 CSV 檔。教師端有一個成績彙整頁，跟第三集講的是同一份引擎，一樣雙擊即可開啟，不需要架站，也不會把資料上傳到網路上。把收到的 CSV 檔拖曳到頁面上的拖放區，就會自動彙整出每位學生的成績，還有每一題全班的答對率。

這一集還安排了一個動手做的練習，是疊加第三份測驗。模組裡準備了一組還沒切題、還沒清理的原始資料，一份共同科目數學考卷，這個練習，是要你從頭走一次「切題清理」加上「一句話生成」的完整流程，把這第三份測驗疊加進已經做好的兩份裡面。第一步，先照第二個模組教的方式，請 Codex 把試題 PDF 切成一題一張圖片，記得共同科目通常是二十五題，要跟 Codex 說清楚正確題數跟科目代號；切完之後，再照清理步驟的做法，請 Codex 執行清理，記得先乾跑一次，確認每張圖都剛好抓到一個題號區塊，才正式塗白存檔。第二步，資料準備好之後，跟 Codex 說：這個問題集資料夾也做好了，請用剛剛提到的那個工具，把它疊加成第三份測驗，不要動到原本已經做好的那兩份。Codex 會自己判斷輸出的 app 資料夾已經存在，用「在既有設定檔裡加一筆」的方式處理，而不是整個重建。完成之後，設定檔應該會有三筆測驗設定，輸出資料夾也應該多一個檔案，另外兩份既有的測驗完全不受影響。這正好證明了一件事：疊加新測驗，不需要重新設計工具。

聽到這裡，可能有人會問：那我是不是就再也不用碰第三集講的那些細節了？我覺得答案是，大多數時候，一句話真的就夠了；但有幾種狀況，回頭看第三個模組會清楚得多。比如說，Codex 回報錯誤或警告，你需要自己看分析報告或打包過程的錯誤訊息排查問題；或者你想手動調整設定檔裡的某個欄位，像是答案選項字母、或者每次作答預設抽幾題；又或者檔名沒有清楚規律，你想搞懂「退回逐題顯示」實際上是什麼意思，會不會影響作答；再或者，你想搞懂雙擊即用的成品，跟可以編輯的原始碼版本，兩種產出之間的差別，或者想在本機測試原始碼版本。這幾種情況，都值得回頭翻一下第三集的內容。

最後有一個提醒，我覺得很重要，值得放在整個系列的結尾：如果你的問題集內容，是有版權疑慮的考古題，比如技專校院入學測驗中心的試題，在把雙擊即用的網頁正式交給學生之前，一定要再次確認自己有沒有合法散布這些內容的權利。這不是技術問題，是使用這整套工具時，你身為老師該負起的責任。

好，那這四集的深度解析，就在這裡告一段落。從第一集搭環境、第二集處理考古題資料、第三集從零設計測驗網頁工具，到今天第四集用一句話濃縮整套流程，這其實是一條很完整的路徑：先懂原理，再享受捷徑帶來的效率。謝謝你一路聽到這裡，希望這系列的內容，能幫助你在自己的課堂上，也把 AI Agent 這套工作方式用起來。我們下次見。
