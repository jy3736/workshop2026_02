大家好，歡迎收聽這系列的深度解析節目，我是主持人。這系列一共會帶你走過四個模組，把一套完整的「Vibe Coding 加 AI Agent」工作坊內容，用聲音的方式重新講一次給你聽。今天先從第一個模組開始，主題是：在 Windows 11 筆電上，把 Vibe Coding 跟 AI Agent 的工作環境，從無到有建置起來。

先說說什麼是 Vibe Coding。簡單講，它指的是一種新的工作方式：你不再是自己一行一行敲程式碼，而是用自然語言，跟一個 AI Agent 對話，描述你想要什麼，讓它去寫程式、改檔案、下指令，你則負責檢查結果、決定要不要放行。這個模組，就是要把支撐這整套工作方式的環境，從零開始搭起來。

在動手裝軟體之前，第一件事是確認電腦夠不夠力。這門課的門檻其實不算太高：六十四位元的 Windows 11，四核心以上的處理器會比較理想，記憶體建議十六 GB，硬碟空間二十 GB 以上比較保險。八 GB 記憶體其實也能把所有任務做完，只是等你同時開著編輯器、瀏覽器，還有好幾個終端機視窗的時候，就會明顯感覺到差別。另外一個容易被忽略的地方，是帳號權限——你的筆電要有系統管理員權限，才能順利安裝軟體，也才能通過安裝過程中跳出來的使用者帳戶控制視窗。

環境建置的核心，其實是七樣工具。第一個是 VS Code，這是你之後操作 AI Agent 的主要工作視窗。第二個是 Git，版本控制工具，很多 AI 工具背後都仰賴它。接著是 Node.js 跟 npm，這一組用來啟動本機的網頁伺服器，也用來安裝 Codex 的命令列工具。再來是 uv，這是專門用來管理 Python 套件跟環境的工具，裝套件、升級、移除都非常單純。然後是 ChatGPT 桌面應用程式，這是 Windows 上進入 Chat、ChatGPT Work，還有 Codex 這三種工作介面的共同入口。最後一個核心工具，是 GitHub CLI，也就是那個 gh 指令，讓你可以用瀏覽器登入 GitHub，完成專案下載、推送，還有部署到 GitHub Pages。除了這七樣，還會一併安裝五個 VS Code 擴充套件：Python、Jupyter、GitLens、ESLint，以及 Codex 專用的編程代理套件。

那要怎麼把這些工具裝進電腦呢？這個模組給了三種安裝方式，我覺得這個設計考慮得蠻周到，因為每個人的電腦環境、還有學校的 IT 權限限制都不一樣。第一種是最傳統的手動安裝，一項一項用 winget 指令裝，如果 winget 沒辦法用，就直接去每個工具的官方網站下載安裝檔。這個方法最保險，但也最花時間，適合前兩種方法都卡關的時候當作後盾。

第二種安裝方式比較特別，是直接打開 ChatGPT 桌面應用程式，用自然語言下一段提示詞，請 AI Agent 自己去檢查電腦上還缺哪些工具、自己依序安裝、裝完之後再把版本檢查的結果回報給你。這個做法背後有個很重要的提醒：要讓 Agent 不需要每一步都等你按核准就能直接執行終端機指令，你得先把工作設定裡的存取層級切到「完整存取權」。但是安裝流程一結束，一定要記得把它切回「先要求核准」，不要讓 Agent 長時間保持在完整存取權的狀態，這是一個安全習慣的問題，模組裡也特別用警告框標出來提醒。

第三種方式，是這個模組直接附的一支批次檔，叫做 module1-setup-windows.bat。你只要把它下載下來，雙擊執行，它會自動檢查有沒有裝過 winget，然後依序把 VS Code、Git、Node.js、uv、GitHub CLI、ChatGPT 桌面應用程式、Codex CLI，還有常用的 VS Code 擴充套件，通通裝好。這支腳本很聰明的一點，是它可以重複執行，已經裝過的項目會自動跳過，不會因為東西裝過而報錯，非常適合當作你回頭補裝、或者換一台電腦時的標準流程。

不管用哪一種方式裝完，都要記得關掉再重新打開終端機，讓系統的路徑設定生效，然後跑一輪版本檢查指令，確認 VS Code、Git、Node、npm、uv、gh，還有 Codex 都能正常顯示版本號。如果哪一項檢查失敗，就回頭用手動安裝的方式，單獨修那一項就好，不用整套重來。

工具都到位之後，真正的重頭戲，是幾項動手驗證的任務。在正式任務之前，模組安排了一個很輕巧的暖身，叫做「Hello, AI Agent」，就是請 Codex 幫你在專案裡建立一個 hello.txt 檔案。這一步聽起來很簡單，但重點其實是讓你完整體驗一次「下指令、Agent 執行、你檢查結果」這個迴圈。這裡有個操作習慣值得特別留意：在 Codex 裡，送出第一個任務之前，建議先選「先要求核准」，不要一開始就打開「完整存取權」，這樣你才能在每一步都看清楚它打算做什麼、產生了哪些變更，再決定要不要放行。

接下來是連結 GitHub。用 gh auth login 這個指令，整個登入流程都在瀏覽器裡完成，用一次性代碼登入，不需要自己產生 SSH 金鑰，也不用在終端機裡輸入密碼，而且這個動作會一次把 git 的認證跟你的提交身分都設定好。設定好之後，就可以練習用 gh repo clone 把專案抓下來，或者用 gh repo create 搭配 push 參數，直接把一個靜態網站發佈成一個公開的 GitHub Pages 網址。

最後是四項驗證任務。第一項是 Python 驗證：用 uv 建一個專案、裝 openpyxl 跟 python-docx 這兩個套件，讀一份 Excel 檔案、整理資料，再輸出一份新的 Excel。第二項是 Word 驗證：讀一份 Word 文件的內容，再產生一份修改過的版本，確認 Office 文件的處理沒問題。第三項是 JavaScript 驗證：用 npx http-server 這個指令，啟動一個簡單的本機網頁伺服器，確認 Node.js 跟本機連線都正常。第四項，則是直接測試 Codex 本身，請它建立一個文字檔、修改一份範例程式，或者整理一份指定的資料，確認 AI Agent 真的可以讀寫你工作區裡的檔案，並且把結果清楚地回報給你。

聽到這裡，你可能會想，這個模組花這麼多時間在「裝軟體」，值得嗎？我的看法是，非常值得，因為接下來的每一個模組——不管是考古題的下載、切題、清理，還是測驗網頁的自動產生——全部都是建立在「這個環境可以正常運作」這個前提上。環境沒搭好，後面每一步都會卡關。所以與其把它當成單純的前置作業，不如把它看成整個工作坊的地基。

好，那第一集就先到這裡。下一集，我們會走進第二個模組，看看怎麼把一份技專校院入學測驗中心的考古題 PDF，變成一題一張乾淨的圖片，再配上一份標準答案的資料檔。謝謝收聽，我們下一集見。
