# AI Agent Prompt：統測試題下載、切題與清理流程（module2 版）

這份文件示範同一個「下載 PDF → 切成單題圖片 → 清理圖片」流程，如何從一則
簡單的自然語言提示詞，逐步除錯精修，最後收斂成三個可重複使用的 Claude
Code skill（`download-exam-pdf`、`slice-exam-pdf`、`clean-exam-question-images`）。
只涵蓋下載＋切題兩階段的原始版本在
`module3/docs/ai-agent-prompt.md`；本文件延伸補上「清理圖片」階段，並記錄
`module2/` 底下兩次實際執行的結果。

## 階段一：簡單的自然語言提示詞

剛開始下指令時，通常只會講清楚「要什麼」，不會預先設想所有邊界情況。以下
三則是實際下達（或改寫自實際下達）的原始提示詞：

**提示詞 1（下載階段）：**

```text
請到技專校院入學測驗中心的網站，幫我下載 115 學年度統測「電機與電子群資電類」的資料。
我只需要專業科目(一)、專業科目(二)的試題，還有這兩科的標準答案。
下載好之後，store in @module2/raw
裡面放專業一題目、專業二題目、專業一答案、專業二答案。
```

**提示詞 2（切題階段）：**

```text
請幫我把下載好的 115 學年度試題 PDF，每一題切成一張圖片，檔名使用 ./assets/repo/<學年度>專業<1 或 2>Q<題號>.png。
然後對照標準答案 PDF，製作 ./assets/<學年度>keys.json。JSON 的 key 使用與圖片檔名完全相同的字串，value 填入正確答案。
```

**提示詞 3（清理階段，本文件新增）：**

```text
剛剛切出來的題目圖片，下面留了太多空白，有些甚至留到下一題的一小段殘影；
題號（像「50.」「11.」）也還留在題目最前面。
可以幫我把每張圖片下面多的空白裁掉，題號也清掉嗎？但是選項 (A)(B)(C)(D) 不能動。
```

這三則提示詞都只描述「想要的結果」，沒有講任何裁切座標、字型、或像素門檻
——這是正常的第一版，接下來才會在真正執行中撞到隱藏的邊界情況。

## 階段二：除錯後精修的提示詞

實際執行後，上面三個任務都各自撞到好幾個「憑直覺寫程式碼會出錯」的陷阱。
把這些陷阱一次講清楚、寫進提示詞，才能重複使用在下一個學年度／科目上，不
用每次重新踩雷。

### 下載＋切題

完整精修版與 10 條已知陷阱請見 `module3/docs/ai-agent-prompt.md` 與
`.claude/skills/slice-exam-pdf/SKILL.md`；這裡只點出後續清理階段會直接用到
的關鍵前提：

- 下載按鈕是 `<input type="image" onclick="...">`，不是 `<a href>`，需解析
  `onclick` 屬性裡的網址。
- 切題時，一題的下邊界＝下一題（或下個題組提示行）的起點，**不加
  padding**——這正是為什麼切出來的圖片下緣常會帶一小段「下一題的殘影」，
  必須靠清理階段的 Pass 1 移除，而不是回頭改切題邊界。
- JSON key 需與圖片檔名完全一致（含 `.png`）。

### 清理圖片（本文件新增的精修版）

```text
對資料夾裡的每張 *.png 依序執行兩個獨立的清理動作：

Pass 1（裁掉下緣多餘空白）：
- 轉灰階，把「有深色像素的橫排」聚成一個個區塊（區塊間空白 ≤3px 視為同一區塊）。
- 找出最後一個「真正內容」區塊：如果最後一塊很薄（高度 ≤8px）且離前一塊很遠
  （間隔 ≥20px），視為切題邊界殘留的殘影，捨棄它，往前找下一塊當作真正結尾。
- 裁到「結尾 + 15px」，多留一點呼吸空間；本來就很緊的圖片就不要動它。

Pass 2（清掉題號，只處理開頭區塊 x ≤ 220 的情況）：
- 同樣先切出橫排區塊；每個區塊裡再依 x 座標切出一段段連續的深色像素
  （間隔 ≤1px 算連續）。
- 只有當「開頭那一段」在 x ≤ 220 開始，且往右第一次出現 ≥14px 的間隙，且
  間隙前面那一叢的結尾 x ≤225、寬度 ≤55px，才判定為「題號＋句點」，塗白到
  「間隙後那段」開始前 2px。
- gap 門檻絕對不要調到 10：兩位數題號（如「11.」）兩個數字中間的間隙可以到
  10px，門檻設 10 會誤判成「數字→文字」的間隙，只清掉半個題號，留下「1.」
  殘影。
- 選項 (A)(B)(C)(D) 一定是從文字起始欄（x≈228 起）開始，不會被誤判成題
  號，不要額外處理它們。

執行前先「乾跑」一次 Pass 2 的偵測邏輯（只印出偵測結果、不要真的塗白），確認：
- 每個檔案剛好偵測到 1 個題號區塊（0 個代表版面跟預期不同；≥2 個代表誤
  判，門檻可能太寬）；
- 所有偵測到的「文字起始 x」要收斂在一個很窄的範圍內（本專案約 231～236px），
  離群值代表門檻需要調整。
確認沒問題才真正執行塗白，並事後用 Read 工具抽樣檢查結果。
```

這一版把「多留一點空白裁掉」「清掉題號但留住選項」這兩個模糊指示，換成了
可重複執行、有明確驗收標準的演算法描述——這正是「精修」的核心：不是換一
個更聰明的提示詞，而是把第一次執行時踩到的每一個邊界情況都寫死進規則裡。

## 階段三：收斂成可重複使用的 skill

當這三個提示詞都各自被驗證過一次、且已經吸收了對應的陷阱清單之後，就不需
要每次重新貼一大段文字——直接把它們包裝成三個 Claude Code skill，之後只
要換學年度／科目、改幾個參數即可重複執行：

| 階段 | Skill | 用法 |
|---|---|---|
| 下載 | `download-exam-pdf` | `python3 .claude/skills/download-exam-pdf/scripts/download_exam_pdf.py --year <年> --group <群類> --subjects 1,2 --out-dir <輸出目錄>` |
| 切題 | `slice-exam-pdf` | `python3 .claude/skills/slice-exam-pdf/scripts/slice_exam_pdf.py --year <年> --subject "<label>:<試題.pdf>:<答案.pdf>" --out-dir <輸出目錄>` |
| 清理 | `clean-exam-question-images` | 對目標資料夾執行 SKILL.md 內的兩段內嵌 Python（無獨立 script） |

三個 skill 各自把「已知陷阱」直接寫進程式邏輯或 SKILL.md 的說明裡，不再依
賴使用者每次都完整覆誦一次陷阱清單——這就是「從自然語言提示詞，到可重複
使用工具」的完整路徑。

**重要限制（執行前務必知道）：**

- `download-exam-pdf` 目前只認得「專業科目(一)/(二)」的列標籤，抓不到
  「數學(A)/(B)/(C)」這類共同科目——數學卷仍需手動取得 PDF 後，直接從
  `slice-exam-pdf` 開始。
- `slice-exam-pdf` 的輸出檔名固定寫死「專業」兩個字（即使 `--subject`
  標籤是字母），數學卷切完後需要手動把 `115專業BQ<n>.png` 重新命名成
  `115數學BQ<n>.png`，並同步改掉 `keys.json` 的 key，才能交給下一個 skill。

## 本次兩次實際執行紀錄

### 執行一：115 學年度電機與電子群資電類（從零下載）

```bash
python3 .claude/skills/download-exam-pdf/scripts/download_exam_pdf.py \
  --year 115 --group 電機與電子群資電類 --subjects 1,2 --out-dir module2/raw/115
python3 .claude/skills/slice-exam-pdf/scripts/slice_exam_pdf.py \
  --year 115 \
  --subject "1:module2/raw/115/115專業一試題.pdf:module2/raw/115/115專業一答案.pdf" \
  --subject "2:module2/raw/115/115專業二試題.pdf:module2/raw/115/115專業二答案.pdf" \
  --out-dir module2/repo/115
```

結果：4 個 PDF 全部 `verify_pdf() OK`；切出 100 張圖片（專業一、二各 50
題）+ `115keys.json`；清理後抽樣檢查（Q1 單位數題號、Q50 雙位數題號＋
【以下空白】、Q15 題組首題）皆正確，全資料夾掃描沒有發現真正的殘影問題。

### 執行二：115 學年度數學(B)（PDF 已在手）

PDF 原本就已下載在 `module3/raw/math-115b/`（`download-exam-pdf` 抓不到這
科，所以這條路線直接跳過下載，模擬「使用者已經有 PDF」的情境），複製一份
到 `module2/raw/math-115b/` 後直接切題：

```bash
python3 .claude/skills/slice-exam-pdf/scripts/slice_exam_pdf.py \
  --year 115 \
  --subject "B:module2/raw/math-115b/115數學B試題.pdf:module2/raw/math-115b/115數學B答案.pdf" \
  --total 25 \
  --out-dir module2/repo/math-115b
```

輸出檔名依上面提到的限制，先產生 `115專業BQ<n>.png`，再手動重新命名為
`115數學BQ<n>.png`（`keys.json` 同步處理）。

**`115數學BQ11.png` 的歷史紀錄**：`clean-exam-question-images/SKILL.md` 的
Notes 裡記載，早期清理 `module2/repo/math-115{a,b,c}` 時，這張圖曾出現約
30px 的切題邊界殘影（`slice-exam-pdf` 的陷阱 #10，非清理階段能安全處
理），需要重新切題才能修正。本次重新執行時，`slice_exam_pdf.py` 已內建對
應修正（`widen_to_block_top`），實際抽查這張圖沒有再出現殘影——是「精
修」真正發揮作用的具體案例：同一個已知陷阱，被修進工具本身之後，往後每次
重跑都不會再犯。

## 小結

- 三個 skill 的分工邊界很清楚：`download-exam-pdf` 只認得專業科目、只做下
  載；`slice-exam-pdf` 只做切題與答案配對，且輸出檔名固定綁「專業」二字；
  `clean-exam-question-images` 只做像素層級清理，不做任何裁切邊界的重新判
  斷。
- 遇到工具能力邊界之外的情況（例如數學共同科目的下載、或切題邊界的殘
  影），正確做法是換一個起點（已有 PDF 直接切題）或往上游修正（重新切題
  而非在清理階段硬修），而不是在下游硬塞規則。
- 這份文件與 `module3/docs/ai-agent-prompt.md` 互補：那份只涵蓋下載＋切題
  兩階段；本文件補上清理階段，並記錄本次在 `module2/` 下兩次完整跑通的具
  體結果，供之後更換學年度／科目時參考。
